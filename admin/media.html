Gérer les médias

Glisse-dépose tes photos (et vidéos, tout en haut de page) directement sur chaque emplacement, ou clique dessus pour ouvrir le sélecteur de fichiers.
Tout est uploadé en direct sur le site — aucune manipulation de code nécessaire. Les photos sont automatiquement converties en WebP (2400 px max, métadonnées EXIF retirées) avant l'envoi.
Exceptions — ces quelques fichiers sont gérés directement dans le code du site (pas via ce panel) : les vidéos de fond de l'accueil (qualité d'origine + version allégée pour connexions lentes), le logo et le favicon (images/), le portrait d'Aya (images/about/). Dis-le moi directement si tu veux les changer, je m'en occupe.

📋 Fiche d'export — photos et vidéos (à lire avant d'envoyer un fichier)

Règles générales pour les photos

  • Format : WebP. Le panel convertit automatiquement JPEG/PNG/HEIC (qualité 82, côté long 2400 px max) et retire les métadonnées EXIF (dont la position GPS). Exporter dès l'origine en JPEG qualité 90+ ou PNG suffit.
  • Couleurs : exporter en sRGB (Lightroom : « Espace colorimétrique sRGB »), sinon les couleurs ternissent sur le web.
  • Pas de texte, logo ni cadre incrusté dans la photo. Sujet centré : le site recadre selon l'écran.
  • Poids cible : voir tableau. Les photos du portfolio de plus de 400 Ko s'affichent en orange dans le panel.
  • Droit à l'image : pour toute personne reconnaissable, garder l'autorisation de publication.

Vidéos de fond

  • .mp4 (H.264), SANS piste audio, boucle fluide de 8 à 20 s, 1920 × 1080 px (illustration devis : 9:7), 24 à 30 images/s.
  • Qualité d'abord : 8 à 15 Mo (20 Mo maximum). Le site charge la vidéo en lecture progressive : elle démarre sans attendre le téléchargement complet, À CONDITION que le fichier soit faststart (option -movflags +faststart ci-dessous).
  • Commande ffmpeg conseillée (compression, suppression du son, lecture immédiate) : 
    ffmpeg -i source.mov -an -vf "scale=-2:1080,fps=30" -c:v libx264 -crf 20 -preset slow -pix_fmt yuv420p -movflags +faststart sortie.mp4
    Si le fichier dépasse 20 Mo, augmenter légèrement -crf (22) ou raccourcir la boucle. Les vidéos de l'accueil (videos/home-bg.mp4, videos/mission-bg.mp4) se changent directement sur GitHub, avec les mêmes règles ; chacune a une version mobile (home-bg-m.mp4, mission-bg-m.mp4, largeur 1280 px, haute qualité, 3 à 5 Mo : même commande avec scale=1280:-2 et -crf 21), puis incrémenter le ?v= dans config/media.js.

Compression en ligne de commande (optionnel)

cwebp -q 82 -resize 900 1200 photo.jpg -o 1.webp

Ou l'outil en ligne Squoosh (squoosh.app) : WebP, qualité 80–85.

Référencement (Google Images)

  • Textes alternatifs : décrire ce qu'on voit, en une phrase, sans liste de mots-clés. Ils se renseignent dans config/media.js : IMG.portfolioAlt (une liste par catégorie, dans l'ordre des numéros de fichier : 1.webp = 1re entrée) et IMG.serviceAlt (une phrase par prestation). Supprimer une photo ne décale pas les autres textes.
  • Noms de fichiers : les photos du portfolio doivent garder la numérotation N.webp (c'est ainsi que la galerie les trouve) ; les autres chemins sont fixes, ne pas les renommer.
  • Hébergement : les images sont servies depuis l'adresse technique workers.dev. Le passage à media.bunkaio.com est prévu (meilleur pour Google Images et la marque) ; il suffira ensuite de changer MEDIA_BASE dans config/media.js.

Suppression et remplacement

  • Portfolio : « × » supprime la photo (confirmation demandée) ; clic sur la photo = la remplacer par un nouveau fichier au même numéro ; « + Ajouter » prend le premier numéro libre.
  • Un navigateur peut garder l'ancienne image en cache jusqu'à 1 h ; recharger la page avec Ctrl+Maj+R pour la voir tout de suite.
  • La suppression demande la dernière version du Worker : cd server puis npx wrangler deploy. Sans cela, le panel affiche « Worker à mettre à jour ».
